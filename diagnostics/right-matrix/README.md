# 右手矩阵诊断

只用于当前 42 键布局的故障右手，不能替代正常固件。使用原来的右手 shield，
行列引脚、方向、矩阵映射和 5 ms 消抖均保持一致。关闭轨迹球、蓝牙、分体
通信和 Studio；所有 42 个键位绑定 `&none`，只产生扫描日志，不输出字符。
不清除主控中保存的键位或配对信息。

在已有的 ZMK west 工作区构建（替换项目路径）：

```sh
west build -p -s zmk/app -d build/right-matrix -b nice_nano_v2 -S zmk-usb-logging -- \
  -DSHIELD=chary_right \
  -DBOARD_ROOT=/绝对路径/Charybdis46/config \
  -DZMK_CONFIG=/绝对路径/Charybdis46/diagnostics/right-matrix
```

刷入后设备名称为 `Chary Matrix Test`，USB 串口仅用于日志，Studio 无法连接，
按键不输出字符是预期行为。
保持正常键盘连接，用日志终端以 115200 波特率打开故障右手的串口。
先不碰任何键观察 3 秒，再依次单击第二行的六个键和第四行的三个键，
每键间隔 1 秒；检查每次按下和松开是否对应一对 `state on/off`。

正常第二行应输出 `row=1, col=0..5`，第四行应输出 `row=3, col=0..2`。
当前源码对应的输入行引脚依次为 D10/P0.09、D21/P0.31、D20/P0.29、
D19/P0.02；输出列引脚为 D4、D5、D6、D7、D8、D9。

2026-11-19 实机原固件记录：单击实体 K 后，出现 `row=3, col=2`、
`position=41` 和 `keycode 0x7002A`（退格），并有多次按下/释放变化，
末次按下至断开前未记录到释放。正常 K 应为 `row=1, col=2, position=20`。
原固件的右侧 PMW3610 已成功初始化，本次未记录到自动切层。
启动时曾丢失日志，因此不能据此断言首次按下的准确时间。

若此诊断固件仍报同样坐标和抖动，需要核对实际行线、D19/D21 接线与焊接、
对应按键/二极管的导通情况；不要只把退格重新绑定为 K 来掩盖矩阵问题。
若诊断固件坐标、释放均恢复正常，再逐项恢复轨迹球和其他模块定位影响。
诊断完成后重新刷入正常右手固件恢复功能。

## 2026-11-19 诊断固件实测结果

已按序测试第二行六键、第四行三键，并单独对照测试 Y/N：

| 测试 | 实际扫描结果 | 判断 |
| --- | --- | --- |
| 第一行 Y | `row=0, col=0, position=6`，按下/释放配对 | 本次正常 |
| 第三行 N | `row=2, col=0, position=30`，按下/释放配对 | 本次正常 |
| 第二行及第四行 | 仅 `row=3, col=2, position=41` 出现事件；其余未见事件 | 异常仍存在 |
| 异常位置 | 多次按下/释放变化，最后保持按下；与原固件 K 的错误坐标一致 | 不是键值重映射能解决的问题 |

轨迹球、蓝牙、分体通信和 Studio 已关闭，故这些模块的运行不是复现此异常
的必要条件。正常 Y/N 事件证明扫描和事件处理没有整体停止；当前证据更指向
第二/第四行线路及 K 支路的电气状态或接线对应，尚需测量定位具体故障点。

断开 USB 和电池后，用万用表确认：

1. 第二行公共行线是否连续接到 D21/P0.31，第四行公共行线是否连续接到
   D19/P0.02；沿线检查虚焊、断线及相邻焊盘桥接。以实际公共行线为测点，
   避免隔着二极管判断通断。
2. 所有键松开时，D21 与 D19 是否存在非预期直接短接。
3. K 开关的两个触点应在松开时断开、按下时导通；检查开关、二极管焊接，
   以及该键与 D6/P1.00 列线的连接。二极管用二极管档核对方向及单向导通。

本轮没有改动正常固件的行列顺序，也没有清除配对或 Studio 设置。诊断固件
继续保持无按键输出，适合等待线路检查结果；它不是已修复的日常使用固件。
